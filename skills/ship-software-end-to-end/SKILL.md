# 软件全周期交付

适用于 Codex 与 Claude Code。目标是完成用户授权的验收终点，而非机械执行固定阶段。技术栈、命令与发布方式以项目事实为准。

## 完成与授权

- 回答、评审、诊断保持只读；实施任务完成实现与必要验证。push、PR、合并、部署使用用户或仓库已有授权，不从普通咨询推断授权，也不对已授权的正常步骤反复请示。
- 在已授权范围持续推进到验收完成。时间、token、探查次数、验证批次、失败或任务困难不是交付半成品的理由。CI 失败需要修复；流水线运行中继续跟进并处理结果。
- 新的高影响操作、真实资金/消息副作用、生产删除或关键业务选择超出已有授权时，先完成安全准备，再请求具体授权。终点授权不扩张任务范围。
- 用户明确催促时，立即压缩可选搜索、重构、美化、重复验证与非必要观察，保留原验收、安全检查和必要交付。写入、迁移、切流不得停在半成状态。只有用户明确暂停或无法解除的真实阻塞才安全停下并说明未完成；催促不等于停止。

## 执行原则

- 当前代码、Git/CI 和必要的运行环境证据用于判断现状；用户要求与已确认规则决定期望行为。历史文档是线索，不用旧快照覆盖当前事实。
- 保护已有脏改动、其他任务和秘密。采用最小必要改动，遵守项目分支、工作区、提交与发布规则。
- 自主选择定位与验证方法。权限、租户、资金、状态机等变更须找全本问题旁路；普通小改动不升级成全仓审计。根因和方案解释以能让用户判断风险为度，不把固定报告作为编辑前置。
- 检查由风险、验收和项目 required checks 决定，不设次数或时间配额。不为低风险、可逆改动添加仅镜像实现的测试；不因等待 CI 重跑本地全量检查。有变更、失败、环境差异或未解疑点再追加验证。
- 仅在平台和用户授权允许、任务独立且收益明确时委派；明确范围、写入责任和交接，不机械派代理、不递归扩散。当前执行者负责整体验收。
- 发布复用既有可追溯制品与恢复路径；不存在流水线时，先判断实际安全缺口，不擅自把任务扩大成建设完整交付平台。
- 最终简述结果、实际验证、目标环境状态与真实遗留项；未验不冒充通过。只固化长期约束，不为每次提交写 Memory 流水账。

## 按需资源

只读取当前任务需要的资源，不按顺序通读。

- 陌生仓库、工作区复杂或基线不清：[项目发现](references/project-discovery.md)。已有项目入口足够时无需通用探针。
- 不确定该验证哪些风险：[验证矩阵](references/verification-matrix.md)。这是选择指南，不是每项必跑清单。
- 部署、迁移或恢复：[发布与恢复](references/release-and-recovery.md)。
- 需要正式发布记录或阻塞交接：[证据示例](references/evidence-templates.md)。小任务直接简短汇报。

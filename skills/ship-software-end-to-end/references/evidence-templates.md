# 交付证据模板

按项目复杂度取用，不要为了填表制造冗长文档。小任务可直接在对话中维护；高风险或多人协作任务应落到项目既有 issue/PR/runbook/发布记录位置。

## 1. 开工对齐

```markdown
对齐：本次要让【用户/系统结果】发生【变化】；保持【约束/不变项】，不包含【范围外事项】。
完成标准：【本地/CI/目标环境】达到【可观测条件】，并具备【回滚/验收】证据。
```

## 2. 基线记录

```markdown
代码基线
- 工作区：
- branch / commit / upstream：
- ahead / behind：
- 工作树与已有用户改动：

运行基线
- 环境 / account / region / namespace：
- current revision / artifact digest：
- health / incident 状态：
- schema / migration version：
- 上一安全版本：

交付路径
- lint / unit / integration / build：
- package / artifact：
- deploy / activate：
- smoke / monitor / rollback：
```

## 3. 改动面地图

```markdown
定位：完整改动面为【入口】→【领域规则】→【数据写入】→【读取/异步消费者】→【交付与运维】。

| 面 | 当前事实 | 拟改动 | 证据/测试 |
|---|---|---|---|
| UI/入口 | | | |
| API/CLI/webhook | | | |
| 权限/隔离 | | | |
| 状态/并发/幂等 | | | |
| 数据/migration | | | |
| 队列/worker/cron | | | |
| 配置/秘密/资源 | | | |
| 文档/审计/监控 | | | |
```

## 4. 根因或设计决策

### Bug

```markdown
根因是【X】，证据是【复现/代码/数据/日志 Y】。
现有保护未拦住，因为【Z】；【其他现象】是后果，不是独立根因。
最小修复为【方案】，同步封住【旁路】，回归保护为【测试】。
```

### 功能

```markdown
当前缺口是【X】；选择【方案 Y】，因为它满足【验收/兼容/可逆性】。
不采用【方案 Z】，因为【明确代价】。
数据与版本兼容边界：【说明】；失败恢复：【说明】。
```

## 5. 验证矩阵

```markdown
| 风险/验收条件 | 层级 | 命令或入口 | 预期 | 实际 | 状态 |
|---|---|---|---|---|---|
| | L0-L6 | | | | |

未执行项：
- 【项目】：【原因】；替代证据【...】；剩余风险【...】。
```

状态只使用：`通过`、`失败`、`未执行`、`待自然业务`。不要把“未执行”写成“通过”。

## 6. 发布前检查

```markdown
- [ ] 目标 commit 已进入正确远端/评审流，CI 全绿
- [ ] artifact source revision 与 digest 已记录
- [ ] current production revision 已重新核对，无未知漂移
- [ ] 配置/secret/容量/证书前置条件就绪
- [ ] migration 累计范围、即时备份、恢复点与兼容性已确认
- [ ] 部署锁、目标环境与账号已确认
- [ ] 上一安全版本可用，回滚/前滚步骤已演练或验证
- [ ] smoke 与观察指标已定义，不产生未授权真实副作用
```

## 7. 发布记录

```markdown
发布
- 时间 / 操作人：
- 环境：
- source commit：
- artifact / digest：
- 发布方式与流水线 run：
- 迁移/配置/基础设施变更：
- 切换前 current / 切换后 current：

验证
- smoke：
- 公网/源站：
- 日志/指标：
- 观察窗口：

恢复
- previous / rollback target：
- 数据兼容边界：
- 实际回滚演练或限制：

遗留
- 待自然业务：
- 需用户动作：
- 已知但不在本次范围：
```

## 8. 用户催促后的完成优先收尾

```markdown
收尾状态：【已完成 / 真实阻塞，尚未完成】
- 当前落点：【worktree / branch / commit / PR / CI / 制品 / 环境】
- 已通过硬闸门：【语法或编译、根因直接回归、diff 审阅、高风险专项】
- 已削减可选项：【仅列可选测试、优化、整理或非必要观察；没有则写“无”】
- 真实阻塞：【权限、外部系统、关键输入或用户明确暂停的证据；已完成则写“无”】
- 唯一下一步：【一条可执行动作；已完成则写“无”】
- 回滚/失败关闭：【当前安全检查点与恢复方式】
```

只有原验收终点和最低硬闸门均成立时选择“已完成”。外部流水线仍在运行、发布未切换或生产事实未核对时继续工作，不能仅因此交接；只有用户明确要求停止，或当前执行者无法解除的真实阻塞存在时，才能选择“真实阻塞，尚未完成”。

## 9. 最终交付

```markdown
已完成【用户结果】。

- 改了什么：【关键变化与文件/组件】
- 验了什么：【实际命令、用例/断言/构建结果】
- 线上状态：【环境、current revision/digest、smoke、观察】
- 回滚状态：【目标与数据边界】
- 遗留项：【没有则写“无”；未做真实外部验收要明确列出】
```

如果终点尚未达成，改为：

```markdown
代码/制品已完成，但整体任务尚未完成：当前停在【阶段】，阻塞条件是【可验证事实】。
已完成的安全工作：【...】；需要【用户/外部系统】完成【动作】后继续【下一步】。
```

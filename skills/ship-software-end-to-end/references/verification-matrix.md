## 一、选择验证层级

先做一次环境 preflight，再执行最窄的快速检查并按风险扩大。不要用一次大而慢的全量测试代替精确回归，也不要机械补齐与改动无关的层级。

| 层 | 目标 | 典型证据 |
|---|---|---|
| L0 静态 | 发现语法、格式、类型、编码、生成物和秘密问题 | formatter check、lint、typecheck、编译器语法检查、secret scan |
| L1 单元 | 证明局部规则与边界 | 正常、边界、异常、回归用例 |
| L2 集成 | 证明真实依赖契约 | 数据库、缓存、队列、文件、API contract、外部 mock/sandbox |
| L3 构建 | 证明可从干净依赖生成运行制品 | 固定运行时、锁文件安装、生产 build |
| L4 包装 | 证明制品完整且无禁入内容 | manifest/digest、入口与动态资源、运行时配置分离 |
| L5 端到端 | 证明关键用户流程跨组件成立 | 浏览器/API/CLI E2E，含鉴权和失败态 |
| L6 生产 | 证明正确制品在目标环境可用 | revision 核对、smoke、日志/指标、观察窗口 |

默认代码改动至少覆盖改动文件的 L0、根因直接回归，以及受影响的 L1/L2/L3；只有产生构建制品时才要求对应 L3。要求部署时再覆盖 L4–L6。只改文档可降低层级，但仍检查链接、生成或文档构建（若项目有）。

开工时为本地验证设置批次预算并把相关检查集中运行；优先服从仓库硬限制，仓库未规定时，范围明确的普通任务通常不超过 5 批。相同 diff 的同一检查只运行一次；只有相关文件变化或修复该批失败后才重跑。CI 是独立最终闸门，不需要为了等待 CI 重复本地全量验证。

## 二、按改动类型追加闸门

### 前端与静态资源

- 构建真实生产模式；检查入口引用的 JS/CSS、动态 import、worker、WASM、字体、图片和 vendor 资源。
- 验证 base path、路由 fallback、缓存头、旧入口与新 hash 的发布顺序。
- 检查目标浏览器/设备、响应式、键盘、无障碍、深色模式和错误态。
- 视觉改动做截图或真实渲染 QA；不能只看源码。
- 部署后从公网或真实 CDN 路径请求入口与深层资源，避免只测源站 localhost。

### API 与领域逻辑

- 覆盖输入验证、权限、所有权/租户、状态机、幂等、错误码和兼容字段。
- 为全部写入入口和旁路加负向用例；不能只测主 UI。
- 检查列表、详情、导出、统计、通知、审计和 worker 是否共享同一口径。
- 对 webhook 验签、重放、乱序、重复和未知业务记录做失败关闭测试。

### 数据库与迁移

- 在支持版本的真实数据库引擎上测试，不用不兼容替身掩盖差异。
- 验证“从零 schema + 全迁移”以及“生产前一版本 → 本次迁移”两条路径。
- 检查重复执行语义；若迁移本就一次性，确保失败可检测、可续跑且不会静默半成。
- 对比迁移前后行数、金额汇总、孤儿、重复、NULL、约束、索引和执行计划。
- 演练备份可读与恢复到隔离库；记录旧代码/新 schema 和新代码/旧 schema 的兼容性。
- 牢记很多 DDL 会隐式提交；不要把脚本失败误报成整份自动回滚。

### 鉴权、权限、多租户与隐私

- 覆盖未登录、错误角色、错误所有者/租户、跨 Host/组织、过期 token 和撤权后访问。
- SQL、缓存 key、对象存储 key、队列消息和审计全部验证隔离维度。
- 使用至少两个隔离主体做 E2E；生产不具备安全测试条件时，在隔离环境覆盖并明确生产限制。
- 检查响应、日志、错误、导出和前端缓存是否泄露敏感字段。

### 金额、支付、退款与外部消息

- 使用整数最小货币单位或项目既定精度；覆盖舍入、上限、负值、重复和并发。
- 验证业务事实快照、幂等号、迟到成功、未知状态和重试恢复。
- 列表/查询不得同步触发不可控外呼。
- 默认用 mock/sandbox/预演；真实扣款、退款、转账、邮件、短信或群消息需明确授权。
- 无法做真实烟测时，记录“代码/发布已验证，真实业务待自然事件验收”，不能写成全链路已验证。

### 队列、worker、cron 与并发

- 覆盖重复投递、进程崩溃、租约过期、逐项 ack、部分成功、乱序和毒消息。
- 验证每个副作用在成功后立即持久化幂等证据，避免整批末尾才确认造成重复窗口。
- 检查调度错峰、锁范围、超时、退避、死信、监控和手动恢复入口。
- 锁要覆盖需要串行的完整临界区；若切流与 smoke 之间允许另一发布插入，必须增加 revision 校验或扩大锁。

### 基础设施与发布代码

- 对 shell 使用 `bash -n`/ShellCheck（若项目有），并测试真实失败传播；特别检查 `!`、管道和 `pipefail` 组合是否会把失败当成功。
- 验证最小权限、固定依赖版本、known hosts、短期凭据、并发锁和秘密不落日志。
- 对“登记但不激活”“激活前失败”“激活后 smoke 失败”“回滚失败”分别演练。
- 自动回滚前确认当前版本确实已切到目标版本，避免激活前失败却误退上一版。
- smoke 后再次核对 current revision，防止并发发布让测试结果归属错版本。

### 性能与容量

- 若改动影响热点查询、循环外呼、序列化、大文件或并发，记录基准前后数据。
- 检查索引、N+1、内存峰值、连接池、队列吞吐、缓存失效和限流。
- 在与生产规模相近的安全数据上验证；无法模拟时给出容量假设和观察指标。

## 三、测试数据与外部副作用

- 使用自动分配 ID、独立 tenant/account/namespace、明确前缀和可回收数据。
- 不复制生产秘密到测试；生产数据如需抽样先脱敏并获得授权。
- 让测试具备重复执行和失败清理能力，但不要用宽泛删除命令清理未知数据。
- 生产 smoke 优先只读；写入测试必须是明确隔离、可识别、可回收且不触发财务/通知的通道。
- 不为“证明可用”主动破坏一个正常外部客户端或登出真人账号。

## 四、CI、构建与制品验证

让本地与 CI 在关键变量上对齐：

- 相同语言/数据库/系统大版本；
- 相同锁文件和干净安装命令；
- 相同环境开关与服务依赖；
- 相同 build/test 入口；
- 相同 migration 基线。

构建一次并晋升同一制品。制品至少包含：

- source commit 与版本；
- 构建时间和工具版本；
- 文件或镜像摘要；
- 依赖/资源完整性；
- 不含秘密、日志、上传、开发缓存和本机路径；
- 运行时可写目录与不可变代码分离。

CI 失败时一次性读取该次运行的全部失败日志，保留首个根因并在下一次提交前批量修完可本地复现项；只有确定是外部瞬时故障才重试。修复 CI 脚本本身时，必须构造会失败的夹具证明它真的能失败。

## 五、生产烟测与观测

根据项目选取最小但有代表性的 smoke：

1. 版本/摘要与目标制品一致；
2. 健康、ready、依赖连接；
3. 公开入口和核心鉴权入口；
4. 一条关键读流程和安全写流程；
5. 权限/隔离负向请求；
6. 静态入口、动态资源、深链；
7. worker/queue/cron 存活和版本；
8. 新增 Fatal/exception、5xx、错误率、延迟；
9. 业务不变量与迁移后数据核对。

同时区分源站 smoke 与公网 smoke。localhost + Host 可以验证源站路由，但不能证明 DNS、TLS、CDN、WAF 或边缘缓存正确。

观察窗口按风险调整：低风险可数分钟；涉及迁移、队列、缓存、流量或外部回调时覆盖至少一个真实处理周期，并留下自然业务验收项。

## 六、记录证据与缺口

每项验证记录：

- 命令或入口；
- 环境与版本；
- 实际结果和关键计数；
- 覆盖的风险；
- 未覆盖原因与替代证据。

不要只写“测试通过”。用“运行 X，Y 个用例通过；未执行 Z，因为……；剩余风险是……”让后续人员能够复核。

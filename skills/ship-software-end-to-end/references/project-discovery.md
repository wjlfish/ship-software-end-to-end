# 项目发现

仅在基线或责任范围不清楚时使用。

- 读取适用的项目入口，按索引查与任务有关的源码、ADR、业务约束和 Memory；不默认加载整套文档或历史。
- 核对工作区、分支、HEAD、远端基线和已有改动。已有可靠结果可复用；并行变更或待发布版本漂移时重新核对。
- 从锁文件、项目脚本与 CI 确定运行时、测试、构建和发布命令。陌生脚本先检查副作用，不能仅因名字含 test 就认为安全。
- 发布/生产排障才读取相关运行事实：版本、环境、配置来源、健康与恢复点；不展示秘密正文。
- 按症状追踪入口、规则、写入和消费者。鉴权、隔离和状态闸门覆盖相关旁路；其余按实际改动选择，不扫描无关业务。
- 无法确认目标环境、未知并行写入、迁移兼容性或恢复点时，不贸然切流。先解决具体缺口并继续不受影响的工作，不能把可处理的失败直接交还用户。
- 脏主目录不自动 pull/rebase/stash/reset/clean；按项目规范在最新基线建立独立任务工作区。重叠且无法安全合并的改动才请求决策。

通用只读探针仅作可选索引：

```bash
python3 <本Skill目录>/scripts/project_delivery_probe.py --root <项目目录>
```

探针不 fetch、不访问生产、不读取凭据、不执行项目脚本。其结果需按需回到原文件核实；已有项目基线工具能解决问题时不重复运行。

已有证据足以实现和验证时就进入施工；新问题用定向读取解决。不设置探查次数、分钟数或固定代理轮数，也不为凑全报告继续搜索。
